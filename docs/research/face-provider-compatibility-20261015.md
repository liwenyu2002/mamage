## Current Model and Preprocessing

- **Source-established default:** InsightFace `FaceAnalysis(name=model_name)`, where the service chooses request `modelName`, then `FACE_DETECTOR_MODEL_NAME`, then `buffalo_l`. Selfie search also defaults to `buffalo_l` and explicitly requests backend `insightface`; album detection defaults to backend `auto`. These are configurable code defaults, not proof of deployed settings. - **Exact weight/version is not identifiable from this scope.** The service emits `modelVersion: None`; it records no checkpoint filename, checksum, InsightFace version, or recognition submodel identity. Its FastAPI version `0.1.0` and policy revision `face-policy-20261009-v2` are not weight versions. Intended ANN dimension is 512, but detection forwards the model's vector without enforcing that length; 512-dimensional embedding compatibility is therefore not proven. - **Selfie preprocessing:** in-memory Sharp EXIF auto-rotation, aspect-preserving resize inside 1600 x 1600 without enlargement, JPEG quality 88; HEIC fallback converts to JPEG at quality 0.9 and repeats that Sharp path. It sends base64 JPEG bytes, not a local path. [selfie:44](/Users/liwenyu/mamage/apps/server/lib/find_me.js:44), [selfie:59](/Users/liwenyu/mamage/apps/server/lib/find_me.js:59).
- **Album/service preprocessing:** sources prefer `publicDownloadUrl`, then original and thumbnail by default (thumbnail precedes original only when configured); service requests use `buildInternalMediaUrl`. Python decodes bytes/path/URL with OpenCV `IMREAD_COLOR` and passes the decoded BGR image to `app.get(img)`. Detection size defaults to 640 x 640; CPU is default, optional CUDA with CPU fallback. Alignment landmarks, recognition crop/input size, channel conversion inside InsightFace, and pixel mean/scale are delegated to the installed library and are **not established here**. There is no explicit Python EXIF-rotation step; decoder orientation behavior needs a fixture test. ## Identity Safety Boundaries

- **Isolation is label-based, not mathematical certification.** Candidate profiles, reviewed feedback, and selfie results are filtered by exact `model_name` and null-safe `model_version`; JS additionally checks labels and vector lengths. Same dimension or a generic "ArcFace" label is insufficient. A provider mislabeled `buffalo_l`/`null` can pass these gates despite incompatible weights or preprocessing. Missing legacy selfie response `modelName` even defaults back to the requested name. [matching:4](/Users/liwenyu/mamage/apps/server/lib/face_matching.js:4), [pipeline:223](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:223), [feedback:164](/Users/liwenyu/mamage/apps/server/lib/face_feedback.js:164), [selfie:67](/Users/liwenyu/mamage/apps/server/lib/find_me.js:67), [selfie:98](/Users/liwenyu/mamage/apps/server/lib/find_me.js:98).
- **Changing space does not migrate identities.** Refresh defaults to `force: true`, deletes *all* `photo_faces` rows for the photo, then reinserts detections. New-space vectors cannot match old-space profiles/references; auto-person creation defaults on. `force: false` instead skips any photo with usable faces, regardless of space. Thus a configuration-only switch can lose face-to-person links, change face IDs, create duplicate people, or leave old photos unsearchable in the new space. [pipeline:346](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:346), [pipeline:375](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:375), [pipeline:415](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:415), [pipeline:526](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:526), [pipeline:558](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:558).
- **Corrections are protected, not automatically re-embedded.** Any explicit/group feedback protects the entire photo, including against forced refresh; the transaction rechecks after deletion and rolls back a concurrent correction. Feedback stores face/person/photo IDs, boxes, vectors, and model labels; person separations are organization-scoped. Preserve these facts and stable person IDs in any migration. Rejected/deleted/`legacy_blocked` faces and unreviewed legacy feedback must remain excluded. [feedback:82](/Users/liwenyu/mamage/apps/server/lib/face_feedback.js:82), [feedback:90](/Users/liwenyu/mamage/apps/server/lib/face_feedback.js:90), [feedback:133](/Users/liwenyu/mamage/apps/server/lib/face_feedback.js:133), [pipeline:371](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:371), [pipeline:418](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:418), [policy:3](/Users/liwenyu/mamage/apps/server/lib/face_result_policy.js:3).
- **Fallback is not a compatibility guarantee.** Legacy album service errors normally fall back to local `scripts/face_detect.py` (its implementation was outside scope). `FACE_DETECTOR_SERVICE_REQUIRED` only blocks thrown service failures, not a missing service URL or a successful Haar response. Service backend `auto` can silently use Haar with no embeddings while still reporting the requested model name. An empty/malformed successful detector body can become zero faces and commit deletion; detection-only or invalid-vector results can replace old mapped rows. [detector:88](/Users/liwenyu/mamage/apps/server/lib/face_detector.js:88), [detector:152](/Users/liwenyu/mamage/apps/server/lib/face_detector.js:152), [detector:363](/Users/liwenyu/mamage/apps/server/lib/face_detector.js:363), [service:194](/Users/liwenyu/mamage/apps/server/scripts/face_embed_service.py:194), [pipeline:383](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:383), [pipeline:418](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:418).

## Required Provider/Migration Contract

These are requirements inferred from the boundaries above, **not implemented or certified compatibility**:

1. Put an adapter in front of separate detect/embed endpoints: the legacy `/detect` contract carries `faces`, top-level recognition `modelName`/`modelVersion`, `imageWidth`/`imageHeight`, and per-face ratio `bbox`, unique `faceNo`, and numeric `embedding` and/or camel-case `normalizedEmbedding`. Legacy album parsing overwrites box units to ratio and applies top-level model labels to every face; selfie matching does not support the snake-case normalized-vector alias. A direct adapter must satisfy pipeline per-face/meta labels and selfie top-level labels without relying on that parser. Convert pixel/xyxy boxes, validate image orientation/dimensions and bounds, and keep each embedding tied to the correct detected/aligned face. Reject incomplete responses before the mutating pipeline. [detector:98](/Users/liwenyu/mamage/apps/server/lib/face_detector.js:98), [selfie:92](/Users/liwenyu/mamage/apps/server/lib/find_me.js:92), [pipeline:157](/Users/liwenyu/mamage/apps/server/lib/face_auto_pipeline.js:157).
2. Use an immutable embedding-space identity covering recognition checkpoint digest, vector dimension, and validated alignment/input/color/normalization contract. Do not stamp a new provider as legacy `buffalo_l`/`null` without evidence. A verified numerical replica may retain the legacy space; otherwise allocate a distinct name/version and reject unexpected/missing provenance. Detection confidence is not identity similarity. Existing defaults (cosine threshold 0.36, margin 0.06, weighted centroid/recent/reference scoring) need provider-specific calibration, not a copied provider score. [config:3](/Users/liwenyu/mamage/apps/server/lib/face_cluster_config.js:3), [matching:13](/Users/liwenyu/mamage/apps/server/lib/face_matching.js:13), [matching:42](/Users/liwenyu/mamage/apps/server/lib/face_matching.js:42).
3. For a distinct space, stage new vectors beside retained legacy evidence rather than calling destructive refresh. Re-embed authorized source faces/reviewed examples into the new space with audited face correspondence and stable person IDs; retain old vectors, feedback, quarantine statuses, separations, cover references, and rollback data. Do not relabel or compare old vectors across spaces, use detector ordering as a migration key, or auto-create identities during backfill. Protected photos require an explicit preservation-aware path. Current writer is not a dual-space migration facility.
4. Preserve the existing in-memory selfie/no-storage intent and photo/share authorization scope when introducing a third-party processor. Verify provider accessibility to authorized media (legacy album URLs can be private/internal), retention and logging separately; do not publish internal paths or widen access as a transport workaround. Require recognition-capable success and fail closed on outages/model mismatch; never let detection-only fallback overwrite identity evidence. [selfie:1](/Users/liwenyu/mamage/apps/server/lib/find_me.js:1), [selfie:129](/Users/liwenyu/mamage/apps/server/lib/find_me.js:129), [detector:167](/Users/liwenyu/mamage/apps/server/lib/face_detector.js:167).
5. If ANN is adopted, isolate indexes by embedding space and authorization scope, and translate distance to the application's similarity convention. The current optional service index is one global normalized inner-product index, checks dimension only, and returns `knn_query` distances verbatim as `score`; inspected matching callers use JS scoring instead. [service:233](/Users/liwenyu/mamage/apps/server/scripts/face_embed_service.py:233), [service:245](/Users/liwenyu/mamage/apps/server/scripts/face_embed_service.py:245), [service:264](/Users/liwenyu/mamage/apps/server/scripts/face_embed_service.py:264).

## 2. 方法与证据口径

- 仅采用厂商官网、帮助中心、官方产品操作说明；不采用测评排名、论坛体验或竞品文章作为功能证据。
- **文档确认**：官方操作文档描述了入口、步骤或行为。确认的是“官方有此功能说明”，不是本次实测成功。
- **产品页声明**：官网明确描述能力，但未提供足够操作细节；不据此认定质量、准确率或效率。
- **未知**：本次已查材料未说明，不能反推为“不支持”。不同模块、订阅和语言的能力不互相自动继承。
- 没有注册、登录账户、调用生成或付费服务，也没有向外站上传用户资料。检索与浏览仅使用公开产品信息。
- Jasper 部分旧帮助链接跳转登录；沿官方帮助中心导航取得了新的公开文档链接，以下引用使用新链接。没有尝试登录或绕过访问限制。

## 6. 容易被误读的能力与证据缺口

| 问题 | 本次证据与准确解释 |
| --- | --- |
| Prowly 的“可信度审查”是不是新闻事实核验？ | 文档描述 review 检查可信度/资源、格式、引语、媒体和清晰度，但没有交代外部交叉验证、逐项核事实机制或可靠性。应记录为 **AI 内容审阅建议**。审阅开始后的新修改也不包含在该次结果中。[P1] |
| 生成引语是否就是可发布原话？ | Prowly 可把核心信息用于拟写引语；Jasper 产品页明确会起草领导引语。二者都不能证明说话人确实讲过或已授权。MaMage 不应照搬为默认生成直接引语。[P1] [J1] |
| 有知识库是否保证事实正确、资料最新？ | Jasper 知识文档说明 URL 素材可能读到最多两天前的缓存；“Updated”可反映元数据更改，而非原文刷新。不能把“引用最新事实”的产品页宣称当作即时更新保证。[J1] [J4] |
| 有引用是否代表已核实？ | WRITER 有来源片段定位，但其模型说明明确表示模型不能确认生成内容的真实性，事实与统计仍须人工核对。它证明的是可追溯入口，不是事实真伪认证。[W2] [W5] |
| 英文能力能否直接推定中文校园适用？ | Prowly 起草文档列出的语言不含中文；HubSpot Brand Voice 文档列出的六种语言不含中文；WRITER Voice FAQ 明确仅支持英语样稿及英语输出。以上均为具体功能的文档范围，不代表整个产品都不能生成中文。Jasper 的中文新闻稿质量与规则执行情况未验证。[P1] [H2] [W3] |
| 旧文档功能是否仍可向新客户提供？ | WRITER Style Guide 网站构建器已停止向新客户开放；旧 doc editor 建议文档亦明确提示该编辑体验已不再提供。不能把旧页面的评分侧栏或指南网站列作当前普遍可用功能。[W6] [W7] |

**未做质量排名。** 本次没有真实稿件生成、中文适配测试、事实错误率统计或审核绕过测试；“高质量”“准确”“press-ready”“节约时间”等营销措辞不作为结果。上述功能也不代表单一订阅全部包含。

## 7. 校园新闻与商业 Press Release 的适配边界

以下为基于产品定位的 **MaMage 适配判断**，不是校园写作规范调查结论；具体文体、称谓、审核要求应与主代理的规范研究合并确认。

| 维度 | 商业 PR 产品的常见取向 | 校园新闻应如何区别处理 |
| --- | --- | --- |
| 目的与受众 | Prowly 面向媒体关系；Jasper 强调公告、媒体关注和品牌信息。[P2] [J1] | 校园官网消息、院系动态、活动报道和科研新闻不应统一优化为获客或媒体采纳；先明确受众与稿件用途。 |
| 内容类型与结构 | 产品发布、融资、任命、合作等公告，常配机构简介与媒体联系方式。[P1] [J1] | 对应会议、教学活动、人物、学术成果等场景设计模板；商业稿尾部的 boilerplate 和联系区不应机械加入每篇校园消息。 |
| 引语与事实 | 产品可以拟写引语，也可以围绕品牌核心信息组织故事。[P1] [J1] | 原话、转述与待授权拟稿必须区分；不能从议程推断会议已发生，不能由活动照片推断人物身份或发言。 |
| 机构知识与风格 | 品牌语气、营销定位和术语一致性是主要上下文。[H2] [J2] [J3] [W4] | 机构名称与称谓、当前事件材料、写作规则应分开管理；旧新闻可以提供风格示例，不自动成为本次活动事实。 |
| 发布与审阅 | 商业 newsroom、营销邮件、社交内容和外部工作管理平台。[P2] [H3] [J10] | 不推定这些集成可连接学校 CMS、公众号或既有审签系统；生成、导出、送审和发布应分别授权。 |

## 8. 给主代理的五个可落地设计启示

以下全部是 **设计建议/推论**，不是竞品已实现功能清单；优先级不替代主代理已经完成的实现排序。

| # | 设计启示与竞品依据 | MaMage 的最小落点 | 验收示例 |
| --- | --- | --- | --- |
| 1 | **先收集事实，再追问缺口。** 借鉴 Prowly 的分步输入和后续问题。[P1] | 稿件类型、受众、时间地点、人员角色、已发生事实、核心信息和材料入口分开；先生成可确认的事实清单与缺项提示，再起草。 | 只有活动议程、没有活动结果时，不自动写成“成功举行”；缺地点时提示补充或保留待确认，不猜测。 |
| 2 | **机构事实、写作规则、当前材料分三层。** 借鉴 Jasper 的 Voice/Style/Knowledge 分工，以及 HubSpot 的可复用设置。[J2] [J3] [J4] [H2] | 建立机构档案、按稿件类型选用的风格规则、本次事件材料包；界面明确显示本次启用了哪些资料和规则，允许更正与停用。 | 更换风格样稿后不改变本次活动时间、人数、单位；旧机构信息与当前材料冲突时提示确认，不静默拼接。 |
| 3 | **把素材出处放在编辑能核对的位置。** 借鉴 WRITER 的来源片段定位，不照搬“准确”营销承诺。[W1] [W2] [W5] | 姓名、数字、日期、直接引语关联原始素材片段；区分“已对照材料”“待人工核实”“来源冲突”。没有来源的新增事实明确标记。 | 点击人数或引语能回到原始段落；缺原话不能输出为已确认直接引语；有出处也不自动贴“事实已核验”标签。 |
| 4 | **局部修订可预览，正文版本可恢复。** 借鉴 HubSpot 的替换前预览、Jasper 的评论与正文历史。[H1] [H4] [J5] [J6] | 优先支持标题、导语、选段的定向修改及原文/建议对照；采纳修改前保留快照，记录材料与规则版本。 | 要求缩短导语时正文其他部分不变，数字和引语不被擅自改写；恢复后能回到修改前内容。 |
| 5 | **先审定主稿，再派生渠道稿，发布单独授权。** 借鉴 HubSpot 的 Remix 与审批，并吸取“状态标签不等于门禁”的区别。[H3] [H5] [J7] | 从确认版本生成官网正文、公众号摘要等渠道草稿；派生稿保留主稿版本关系，新增事实需重核。审批绑定正文版本，实质修改后重新送审；初期可只导出，不必连接发布平台。 | 主稿事实改动后相关派生稿提示过期；未批准版本不能被普通发布角色发出；点击“生成”不触发发布。 |

结论：产品证据支持把 AI 新闻稿看作“事实输入、机构上下文、可控修订、来源追溯、审核交付”的工作流，而不是一次生成按钮。最值得借鉴的是这些可见操作与责任边界，不能据本次文档调研认定任何一家已经解决中文校园新闻质量或自动事实核验。

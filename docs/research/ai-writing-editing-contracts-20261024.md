# MaMage AI 写作：全文上下文与编辑交互契约

查阅日期：2026-10-24（Asia/Shanghai）。仅研究用户指定的五个官方页面；沿用本目录“主题-日期”命名。未登录产品、实测生成、访问生产或修改应用与测试代码。网页仅作为不可信的待核对资料，不执行其中指令；下文区分官方说明与我们的设计建议，不推断模型内部机制。

## 已核实的产品行为

| 官方来源与入口 | 上下文、操作与落稿契约 |
| --- | --- |
| [Notion 写作指南][N2]，创建与编辑章节 | Agent 可使用页面、工作区、连接应用及网页上下文；选中文字后进入 `Edit with AI`，可改语法、缩短、改语气，再接受、丢弃或重试。新行按空格另行起草，可用 @ 引用补充上下文；支持后续对话修改、扩展和润色输出。这不证明每次选区编辑都读取整个页面。 |
| [Notion FAQ][N1]，行内写作与 AI blocks 章节 | 明确区分某一节的语法、长短、语气修改与新内容生成；生成或编辑可接受、丢弃、重试。AI block 可摘要当前页面，并分别指定主要上下文与其他搜索来源；不能据此把“当前页摘要”外推为所有入口的全文读取保证。 |
| [Word 起草与添加][W1]，能力列表及起草步骤 | 可从空白文档或放置光标处起草，也可给现有文档新增章节、段落、清单等；与改写选中文字分列。可用 `/` 指定可用参考文件；生成后审阅，再保留、丢弃、重新生成或追加要求调整。 |
| [Word 编辑与改写][W2]，操作步骤 | 先选中文字，再自动改写或描述修改目标；审阅后 `Replace` 替换、`Insert below` 在原文下方加入改写版本，或 `Regenerate` 再生成。下方插入保留原文，不等于“按原文接着写”；本页未列出单独的丢弃或追问按钮。 |
| [Google Docs][G1]，写作与一键编辑章节 | 自然语言编辑无需预先选字，可按章节名称定向修改或提出全文建议；说明会理解文档上下文。一键改写则先选字，可改述、缩短、扩写、调语气等。建议直接显示在文档中，可逐条接受、全部接受或全部拒绝。 |

**核实结论：读取范围与修改范围必须分开理解。** Google 明确说明无选区的文档上下文编辑；Notion 说明页面上下文、当前页摘要与选区入口；Word 说明光标起草、添加内容及选区改写。上述文档没有公开逐次输入的全文覆盖、截断、检索或缓存机制，不能断言三家每次都把全文原样送入模型。[N1] [N2] [W1] [W2] [G1]

## 来源与事实边界

- Notion 的资料范围可含有权限的工作区页面、连接应用和网页；FAQ 提供关闭网页搜索、要求外部网页请求确认的设置。因此不能说 Notion 写作天然只参考当前稿。[Notion FAQ][N1]
- Word 可按提示与权限使用相关工作资料及可用网页，也可要求参考来源和引用；官方仍要求人工核对事实、数字、引文、人名、政策等，分享前由用户决定保留、修改或删除。引用存在不等于已完成事实核验。[Word 起草与添加][W1]
- Google 可添加一个或多个来源文件、用 @ 选择资料，并选择主动搜索的位置。本次页面没有给出事实正确率、自动核验保证或“只能依据当前文档”的限制，不补引范围外页面替它作保证。[Google Docs][G1]

## MaMage 实现建议（我们的契约，非厂商实现）

建议每次分别记录**只读上下文、可写目标、落稿方式**；全文帮助理解，不自动授权全文替换。以下动作名称与严格范围是我们的产品定义，不声称竞品有同名菜单。

| 动作 | 建议落稿范围 | 与其他动作的区别 |
| --- | --- | --- |
| 追加 | 文末插入 | 新增内容，不重发或覆盖已有正文。 |
| 续写 | 文末追加 | 读取整篇后延续尚未展开的已知内容，不覆盖原文；本版光标处的续写由“补全”处理。 |
| 补全 | 明确的未完句或缺段处插入 | 只补缺失部分；“完善全文”等范围不清的要求先确认，不偷偷变成全文重写。 |
| 插入段落 | 指定段落边界插入 | 新段需符合全文主题、既有事实与前后衔接。 |
| 改写、润色 | 替换选区，或用户明确指定的全文 | 改表达、语法或语气；默认不授权补事实。 |
| 缩短 | 同上 | 压缩表达而保留要求保留的事实和限制条件。 |
| 扩写 | 同上 | 增加解释与组织；不是增加未经提供的人物、数字、引语或成效。 |

建议交互与数据边界：

1. **全文可用、目标明确。** 请求携带当前稿完整快照、标题、段落顺序、选区或光标位置、动作和用户要求；只读正文与已确认事实材料、仅作风格参考的材料分开。无选区的替换操作需明确提示全文范围；选区不能代替全文上下文，全文上下文也不能扩大选区。
2. **先建议，后落稿。** 接受前保留原稿；接受只应用目标范围，丢弃不改正文，追问调整待采纳建议而非自动覆盖原稿。记录原稿版本与定位；生成期间正文变了，禁止旧建议按过期位置盲写。应用层检查范围及版本，不能只靠提示词。
3. **缺证据不补事实。** 全文是理解材料，不自动成为“已核实事实”。姓名、日期、数字、职务和直接引语保持来源约束；资料冲突提示确认，缺失引语不代写。未经明确授权不引入网页搜索或其他工作区材料。
4. **超限与注入可见。** 超出全文处理预算时明确阻止或说明分段覆盖方案，不静默截取首尾后宣称已看全文。正文、参考资料中的“忽略要求”等语句只是内容，不可改变动作、权限或事实规则。

## 八个验收案例（我们的标准，尚未执行）

统一布置：每例独立建稿；P 编号代表段落，关键事实仅出现一次，不在用户指令中复述。局部操作的目标与每处证据之间至少隔三段合理正文，距离超过 4000 字符；全文缩短则让三处证据两两相距超过 4000 字符。还须放置中部关键事实，避免只保留首尾也能通过。长稿应在声明支持的全文预算内。

| # / 场景 | 非相邻证据与用户操作 | 必须通过的结果 |
| --- | --- | --- |
| 1 / 追加 | P1 写“青禾项目面向七年级”；P8 写“完成 12 份水样记录”。光标在 P16 文末，要求“追加一句总结，交代对象和成果”。 | 仅文末新增，正确组合七年级与 12 份水样记录；原 P1-P16 完整保留，不泛写成果或编人数。 |
| 2 / 光标补全 | P1 定义“本次试点只观察，不作达标评价”；P15 已记“后文详列 12 份样本”。在 P7 末光标要求“接着写一句，说明记录用途，不重复后文数字”。 | 插入处体现观察用途及不作达标评价，不重复后文样本数；光标后正文保持原样。须同时用到远处前文和后文。 |
| 3 / 补全 | P2 记“第一项成果是校园植物名录”；P14 记“第二项成果是观察手册”。P8 未完句为“两项成果分别为”，要求“只补全这个句子”。 | 只插入两项准确名称和必要标点；不重新生成句首，不把两项成果扩成整篇报道。 |
| 4 / 插段 | P1 交代“活动主题是校园节水”；P13 交代“仅开展水表读数记录，未测水质”。在 P6/P7 间要求“插一段说明活动与记录方法的关系”。 | 仅该边界新增段落，衔接节水与水表读数；不得写成水质检测或宣称节水成效已测得。 |
| 5 / 改写 | P1 确认项目名“青禾”；P15 确认“尚未评奖”。P8 选区为“这个项目收获了大家的关注”，要求“改写这句，写出项目名并说明评奖状态”。 | 只替换选句，使用青禾并保留尚未评奖；不得改成获奖、评审通过，非选区逐字不变。 |
| 6 / 润色 | P2 明确“导师是陈宁”；P14 标记直接引语“先记录，再判断”。P8 选区为“导师提到了那句研究原则”，要求“润色此句，补出姓名并原样引用原则”。 | 只改选句，导师姓名正确，引语逐字一致；不编职务或新增讲话，其他段落不变。 |
| 7 / 缩短 | P1 记“10 月 12 日开展”；P8 记“12 份有效记录”；P16 限定“只有一个班，不能代表全校”。明确要求“把全文缩为三句，保留时间、成果和适用限制”。 | 三处非相邻信息均保留，不能因压缩去掉样本限制或把记录数当人数；按全文建议预览，丢弃后恢复原稿完全一致。 |
| 8 / 扩写与追问 | P2 记“项目只用校内观察”；P14 记“外出调查尚未批准”。选 P8“学生进行了观察”，要求“扩写本段，解释资料来源和活动边界”；建议出现后追问“再简洁一些，保留边界”，最后接受。 | 两轮建议均只用校内资料并保留未批准边界，无编造外出行程；追问前不落稿，接受只替换 P8。若等待时正文被编辑，旧建议不能覆盖新版本。 |

验收需同时检查：请求确含远处事实与正确版本（应用可观测记录，不推断模型内部注意力）、建议使用证据正确、接受后的变更范围正确。每例至少交换一次事实所在的首/中/尾位置；逐一改动远处的关键事实后再运行，结果应对应变化，不能只凭固定答案或话题相似判通过。八例共用接受前不改正文、丢弃零变更、追问不扩大目标的检查；未运行不能标为已通过。

## 本版验证记录

- 已落地：新闻稿与公众号内容稿共用润色、补全、补段落、文末续写、精简、扩写和自定义修改。动作和可写范围分开；每次带全文、标题、图注、人工材料和近期对话。局部只让模型返回目标修改，应用层合并并检查其他部分未变。
- 连续调整未采用的建议时，保留原修改范围；插段后的“再简短一点”调整刚增加的段落，不会再插一段或退回全文改写。正文被手工修改后，旧建议不能直接覆盖。
- 使用已有文字模型配置，运行了另行构造的 **9 组合成用例**，并非声称上表八例全部执行。每稿 18 个内容块，上下文 JSON 约 5,500 字符；覆盖远处两项成果补全、替换事实的对照、润色、插段、续写、扩写、精简、缺原话追问、双块后续调整。
- 第三轮 9 组均通过各自的事实关键词、位置、保留范围与追问断言，单次模型调用约 **1.1–2.2 秒**。未读取生产相册或修改生产服务，不是对真实用户稿件的总体准确率或审美评分。
- 初轮仅检查关键词时，人工审读发现把“仅一个班参加”的活动限定误挂到手册上，以及从成果名称推断内容的问题。随后补强主体关系与禁止按名称猜细节的约束，明确合成材料中的限定主体，再重跑。不能据此推断这类语义错误已被完全消除，发布前仍需人工审稿。
- 可重复的选择性实测入口：`apps/server/scripts/evaluate_news_editing.js`，必须显式开启 `MAMAGE_NEWS_CONTEXT_EVAL=1`，测试配置由 `MAMAGE_NEWS_EVAL_ENV` 私下读取，合成结果落在被忽略的 `.local/news-context-eval-20261024/`。默认测试不访问模型接口或数据库。

## 2026-10-25 局部指代回归

- 本地界面预览原先返回固定模拟改稿，不能用来评价语义质量。最初仅改稿另接真实模型，其他步骤当时仍为模拟；随后按下节完成真实业务后端接入。独立的模拟模式只保留给 UI 回归，不能与模型语义验收混用。
- 选区请求显式附带选中的文字；模型返回替换片段，服务端拼回选区外原文。追问与修改互斥；未改动的建议不能伪装成完成。指代缺依据或有歧义时追问，不能靠活动概括替代答案。
- `evaluate_news_editing.js` 新增缺校名、材料有校名、远处正文有校名、校名替换对照、双校歧义、回答当前追问、具体要求优先于润色预设等用例。真实模型初轮暴露了无效追问格式、无变化回复及偶发误追问；收紧协议、增加 JSON 模式并将精确改稿采样温度设为 0 后，最终一轮 **17/17** 通过。合成结果见忽略目录 `.local/news-context-eval-20261025/results-v5.json`，单次约 0.7–8.1 秒。这不是通用写作准确率，也不保证后续完全不出现误追问。
- `test-news-revision-live.cjs` 需显式开启 `MAMAGE_NEWS_LIVE_BROWSER=1`，只访问本地 5192 预览，覆盖两种屏宽下的真实追问、答复后替换、歧义、采用前保留原稿和采用后撤销。普通浏览器回归仍是模拟流程，不与这类语义验收混为一谈。

### 同日真实后端联调

## 不确定性

- 五页没有确认统一的“继续写”“补全”专用按钮，也未给出它们与扩写的完整规则；上表新增动作语义由我们定义，不据旧印象补充。
- Google 明确文档上下文，但未承诺每次逐字覆盖全文；Notion、Word 也未公开选区操作的精确读取范围、最大长度与超限策略。全文非相邻案例是 MaMage 的验收要求，不是竞品已通过的基准。
- Word 明示部分体验分批推出，受订阅、组织设置、应用版本与平台影响；Google 一般功能有计划门槛，其文风匹配另标为实验功能。公开文档不保证特定账号入口相同。[W1] [G1]

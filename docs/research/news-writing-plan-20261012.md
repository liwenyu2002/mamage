# MaMage 新闻稿功能调研与改进方案

查阅日期：2026-10-12。代码基线：`a1ef72e2`。本文件为设计建议，不代表功能已经上线；没有修改生产配置或数据。

## 结论

建议将新闻稿功能定位为“有事实依据的校园采编助手”，而不是“输入几句话就产出可直接发布的文章”。优先解决事实边界、任务可靠性和修改成本，再提高文风质量。

建议流程：导入活动素材 → 整理并确认关键事实 → 生成初稿 → 对照来源核对、局部修改 → 人工审定与导出。结构化素材已经完整时，跳过 AI 提取步骤，避免每篇文章固定串联多次模型调用。

市场产品的一手资料与逐项比较见 [AI 新闻稿产品调研](ai-news-products-20261012.md)，包含四款海外产品和新华妙笔盒子、人民网写易的国内参照。商业 PR 的产品能力可以借鉴，但商业宣传稿的营销语气、公文写作的固定结构不能直接套用到校园新闻报道。

## 现有功能与缺口

以下是代码检查结论，不等同于对每条用户操作进行过线上端到端测试。

已有基础：照片与采访文字输入、五种渠道模板、组织默认风格预设、异步任务与数据库恢复、逐渠道重试、规则核对、Word 导出与公众号排版器衔接。不是从零重做这些能力。

## 写作规范如何落地

### 通用底线

《中国新闻工作者职业道德准则》强调核实信息来源、准确呈现事实和禁止虚构，并要求尊重隐私及作品版权。对 MaMage 的直接启示是：不能把模型补充的细节当事实，也不能把风格参考文章里的事件信息混入本次报道。[准则全文](https://www.xinhuanet.com/politics/2019-12/15/c_1125348618.htm)

AP 于 2026 年 7 月更新的说明列出资料摘要、转写、标题建议和文字校改等 AI 辅助用途，同时保留人工审核与编辑责任。这是其自身 newsroom 规范，不是中国校园统一适用的制度；这里借鉴的是人工负责、来源可核对的原则。[AP 官方说明](https://www.ap.org/the-definitive-source/announcements/ap-updates-newsroom-standards-for-artificial-intelligence/)

### 建议的校园新闻默认规范

以下是结合公开采编规范提出的 MaMage 默认配置，最终应由本校宣传部门审定，而不是宣称全国学校都有相同格式。

| 部位 | 建议默认行为 |
| --- | --- |
| 标题 | 写清真实发生的事件及其新闻点，不用夸张词代替信息；提供三种不同角度的备选，不只改同义词 |
| 导语 | 先交代最重要的事件，兼顾必要的时间、地点、主体；不强塞全部 5W1H，也不罗列全部出席人员 |
| 正文 | 围绕实质内容、可验证成果和必要背景展开；避免逐条照抄议程的流水账 |
| 人物与机构 | 姓名、职务、主承办关系人工确认；机构全称、简称和职务按活动发生时的有效信息处理 |
| 引语与数据 | 直接引语保留原文依据；转述不得包装成原话。无来源的人数、金额、荣誉、承诺不补写 |
| 图说 | 对应实际画面、环节、已确认人物与摄影署名；图片中出现某人不等于已核实其职务、发言或组织关系 |
| 结尾 | 有已确认成果就写成果，有明确计划及来源才写计划；不强制主观升华，也不虚构未来承诺 |
| 稿件状态 | 默认“AI 初稿／待核对”，人工审定前不能标成“审核通过”或自动发布 |

华中师范大学的采编规范提供了很具体的参考：重新闻价值、简练导语、核准职务、克制主观评价，以及不机械添加未来展望等。但其字数、电头、人员称谓和日期写法属于该校口径，不能全盘硬编码到本校。[华中师范大学采编规范](https://news.ccnu.edu.cn/info/1081/9914.htm)

例如，天津农学院公开流程与华中师范大学对开篇时段的要求就不同，前者举例包含上午／下午，后者要求不写。这说明应当把日期展示、署名、电头和导语长度做成机构配置，不应让两种规范互相覆盖。[天津农学院发稿流程](https://xcb.tjau.edu.cn/info/1022/1031.htm)

标点、数字等文字形式可参照现行推荐性标准，但不能将格式合规等同于新闻事实正确：[GB/T 15834-2011 标点符号用法](https://std.samr.gov.cn/search/stdPage?q=GB%2FT15834)、[GB/T 15835-2011 出版物上数字用法](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D7DA87D3A7E05397BE0A0AB82A)。

### 分清三个维度

- 稿件体裁：校园消息、事件通讯／人物报道、工作简报。通讯不是上级报送公文的同义词。
- 发布渠道：官网、公众号、小红书、微博。更换渠道只能改变结构与语气，不能增加事实。
- 活动主题：党团思政、学术讲座、文体活动、社会实践等。主题影响素材侧重，不应触发无依据的政策引用和价值评价。

涉及党团主题，优先呈现具体育人举措、师生行动与实际成果；政策名称、届次、年份及固定表述使用经确认的原文。没有采访或文件支撑时，不代领导表态、不替参与者写感受。

## 建议的产品流程

### 1. 素材进入，而不是先填一长串表单

允许从相册带入标题、活动日期、环节与选定照片，或粘贴活动方案、现场记录、已有草稿。结构化字段已填好时直接使用；非结构化长资料才调用一次提取。

素材明确分为三类：本次活动的事实材料、只用于学习文风的历史文章、尚未确认的识别线索。活动方案中的计划不自动当成已发生事实，历史样文中的人物和数据不进入当前事实包。

### 2. 确认一张事实清单

AI 整理出时间、地点、主承办方、主要人物与职务、关键过程、结果、原话和数据。每项带来源片段与状态：已确认、待确认、材料冲突。

只重点追问影响真实性的缺口，例如两个材料日期冲突、职务不明、是否实际获奖。可省略的缺失信息不强迫用户补齐，也不让 AI 猜。素材不足时允许生成较短稿件，不为达到目标字数编细节。

### 3. 成稿和核对共用一套事实

按体裁、渠道和机构规范生成三条备选标题及一篇正文。事实编号与段落对应保存在内部，阅读稿不出现技术标记。

核对区显示三类内容：明确冲突、缺乏依据、写作建议。点击能定位正文与原始资料。引用编号由模型给出也不自动证明对应关系正确，人工仍需查看来源。

### 4. 局部改稿，不再反复整篇重写

提供精简、扩写导语、改写选中段落、降低宣传语气等操作。锁定已经核对的事实和用户已确认的段落；AI 提议以新版本展示，差异对比后接受，原稿可恢复。

“官网新闻”先完成一版可靠底稿，再按需改写公众号或其他平台；多个渠道共用确认事实与版本号，不让每个平台各自补细节。并非要求所有渠道必须串行等待同一篇文章。

### 5. 编辑体验

电脑端以正文为主，左侧素材、右侧核对可折叠；手机端在素材、正文、核对之间切换，不把三栏硬塞进屏幕。沿用统一组件和液态玻璃样式，不为长篇阅读增加重型折射动画。

主操作保留生成初稿、保存版本、导出，其他修改动作放在选区工具或菜单里。自动保存应带账号与小组织范围，切换账号不恢复他人的草稿。

## 技术与性能建议

- 继续使用现有异步新闻任务、数据库恢复和独占锁，补齐前端恢复与任务状态，不重复搭一个新队列。
- 前端显示排队、整理资料、生成、检查、完成／失败等真实阶段，只报告已经实现的阶段；同时显示等待时长，不用固定时间推算 99%。
- 第一版可继续轮询，做可见性控制与退避；流式预览后续再加。流式文本是未检查的草稿，结构化 JSON 未结束时不能当作最终稿。
- 生成请求增加幂等标识；同一次请求重复点击不重复建批次。取消要真实传到上游请求，并防止取消后的晚到结果覆盖新版本。
- 一般稿件由快速模型生成；默认先用确定性规则检查。复杂事实关系或风险提示再按需调用第二次语义核对，而不是所有稿件固定多轮“代理辩论”。
- 组织全称、称谓、规范和样文片段按组织与小组织权限读取、版本化缓存；不直接塞全部历史稿，也不跨小组织取私有材料。第一版无需先搭重型向量数据库。
- 目标字数、配图数、输出协议共同决定输出预算；检测 `finish_reason` 与字段完整性。格式修复、网络重试和内容重新生成分开处理，不能把截断稿伪装成成功。
- 持久化模型标识、规范版本、来源版本、耗时和错误类别，凭数据判断是否需要换模型。模型温度降低只能改善稳定性，不能保证不编造事实。
- 发送到外部 API 的资料最小化，不发送对象存储密钥、私有下载签名或无关个人信息。后台鉴权后解析素材，模型只看必要的文字与内部照片编号。

## 第一轮实施顺序

| 顺序 | 范围 | 可验收结果 |
| --- | --- | --- |
| P0 | 去假进度、刷新恢复、幂等、保存旧版本、接通写作要求、统一错误状态 | 刷新与短暂断网不丢任务；重复点击只建一个批次；重写不覆盖旧稿；页面设置真正进入请求 |
| P1 | 事实包、候选姓名确认、来源类型、重写危险模板、真实核对面板 | 无来源的引语和数据得到提醒；样文和计划书不被当成已发生事实；姓名与职务能追溯 |
| P2 | 按体裁组织的编辑页、标题备选、选区修改、版本差异、导出 | 不需要整篇重写就能修一段；切换设备与账号不会混入他人草稿 |
| P3 | 共享事实的多渠道改写、学校定制规范、根据采编反馈优化 | 同一事实在官网与社媒保持一致；规范更新有版本，保留人工审定记录 |

这里的优先级不是上线承诺，也不是要把完整审批系统一次做完。第一版可以先记录核对与审定状态，学校的实际审批制度另行确认；不默认公开发布。

## 评估办法

建立约 20-30 份经授权或脱敏的校园素材包，覆盖会议、党团活动、讲座、获奖、文体与实践；同一资料对比当前版和新版。评委以不知道版本的方式判断新闻点、结构、规范性和修改成本，不只看“是否像 AI”。

专门设置缺失与冲突样例：无讲话原文、无人数、计划未落实、日期冲突、人脸候选误认、历史样文带旧人名、资料中的提示注入、无配图和输出截断。

记录无依据事实数量、姓名／职务／引语错误、来源对应准确性、人工修改时间、任务恢复成功率、p50／p95 成稿时间和每稿成本。建议首轮以 500-800 字常规稿 p50 不超过 30 秒作为待压测目标，不是当前已经证明的承诺；此前一次 437 字符（含 Markdown 符号）生成约 11.5 秒，只能说明当次通路正常，不能代表稳定性能。

性能测试覆盖同时 1、2、4 个新闻任务，检查新闻队列不会挤占图片与视频分析。正确性测试同时覆盖后端结构化输出、前端刷新恢复、已取消任务晚到和新旧版本竞争。

验收底线：固定测试集中不能静默补写缺失引语、姓名和人数；发现冲突要显示待核对；规则检查无异常不能标记“事实完全正确”。这不能外推为上线后零错误，所有对外发布仍需人工审核。

# 部署与回退

## 单一发布源

- GitHub：私有仓库 `liwenyu2002/mamage`，分支 `main`。
- 开发目录：`~/mamage`。
- 服务器连接：`ssh liwenyu@10.11.12.63`。
- 线上仓库：服务器上的 `~/mamage`，仅拉取，不直接修改。
- 发布目录：`~/mamage-releases/<提交号>-<时间戳>`，已发布源码不再修改。
- 当前版本指针：`~/mamage-data/current`。
- 私有配置：`~/mamage-data/config/server.env` 与 `web.env`。
- 日志与临时数据：`~/mamage-data`；对象存储、MySQL、现有模型位置保持不变。
- 兼容入口：Nginx 仍读取 `~/mamage-web/dist`，该目录现在指向当前版本的前端构建。

服务器使用专用只读 GitHub 部署公钥，不保存开发者的 GitHub 令牌。
人脸 Python 环境继续使用原有安装位置，代码未改变时不重启人脸服务；改变时沿用原进程参数和模型配置。

## 日常更新

本地完成代码提交后，在仓库根目录运行 `npm run deploy`。服务器固定发布指定提交，而不是发布运行期间变化的“最新代码”。

步骤：锁定发布 → 导出已提交源码 → 按锁文件安装依赖 → 前后端测试和构建 → 验证生产配置 → 数据库与文件夹状态备份 → 重启 API → 原子切换前端 → 只读冒烟验证 → 保存进程配置。

构建或测试失败不会切换线上版本。切换后检查失败会恢复旧进程及前端指针。保留旧哈希资源，避免已打开页面因缺少旧分包而白屏。发布锁阻止两次部署同时执行。

可用磁盘小于 3 GiB 时拒绝新发布，避免构建挤占线上运行空间。版本与备份暂不自动删除，需定期检查容量。回退不重启未改变的人脸服务；如需恢复人脸代码，先恢复人脸服务，再启动 API。

此流程不自动执行数据库结构迁移，不重跑分析、不重分配相册、不删除照片，不恢复覆盖生产数据库。

## 手动代码回退

```bash
ssh liwenyu@10.11.12.63 '~/.local/bin/node ~/mamage/scripts/deploy-remote.cjs --rollback'
```

回退至上次成功发布之前的代码和进程配置。数据库保持现状。回退后先调查原因，再做下一次发布；不要直接改发布目录，也不要删除仍被引用的版本。

如果发布被强制中止，先确认没有部署进程，再检查 `~/mamage-data/deploy.lock`。不要在部署仍运行时删锁。

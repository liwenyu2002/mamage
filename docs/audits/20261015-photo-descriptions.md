# 照片双层描述：实现与隔离验证

当前状态：2026-10-16 已按用户确认部署到生产，revision 13 执行两项新增迁移，revision 14 修复不确定人物空结构导致整组失败的问题。历史照片通过持久队列回填，尚不能宣称全量完成。此前的隔离试验记录保留在下文；代码未提交或推送。

## 行为

- 保留 `photos.description` 短摘要，新增可空的 `photos.detailed_description`。已有摘要不做数据迁移或扩写；没有详情的旧照片保持原有展示。
- 识图输出 `description` 与 `detailedDescription`，不设最低字数。短摘要提示为 30–60 字，保留原来 160 字符的兼容上限；详细描述最多 800 个 Unicode 字符，不补足字数。
- 当前 Hub 路径增加一次同图描述复核，仅复核两段文本，不改选片分数。人物衣着、动作、物体与相对位置只描述可见内容；不猜身份、年龄、背景或心理；转录文字应留在独立 OCR 字段。
- 生成与复核均关闭思考，输出预算分别为 2048 / 1536 token，结构化 JSON 在客户端校验。复核不可用时不保留未经复核的详细描述，短摘要和已有评分能力保留。`reviewed` 只表示完成模型复核，不表示事实已被人工认证。
- Worker 分字段保存；缺少新列时报失败，避免静默丢掉新字段却标成保存成功。组织复制将新字段一起复制。
- 详细描述只随有权限的单照片详情返回，不加入相册/搜索列表载荷。打开照片后按需获取，展开阅读；切换或关闭时取消旧请求，避免上一张结果串入当前照片。
- 本次没有把详细描述接入新闻稿事实来源，也没有改变检索排序、选片阈值、人脸识别或视频语义。

## 已发现的问题

初始单次输出仍会重复抄写文字、猜测小字或加上年龄/活动定性。保留了所有试跑输出，没有人工替换模型描述或只展示成功案例。

追加复核后，描述更短，转录文字和部分推断被移除，但仍不能保证正确。例如三人舞台仍误写“双手握麦克风”，原图是一手持麦克风，另一手持纸条；海报主题、物体材质、排列形态和具体乐器型号也存在需核对的细节。OCR 本次没有做独立视觉复核，仍存在错读，不能直接当作新闻事实。

因此当前结论是双层描述功能和隔离验证已完成，不是“无幻觉”或“准确率通过”。样本预览逐张标注了这些限制，后续上线与全库回填需另行决定。

## 2026-10-16 人物结构化观察（隔离验证记录）

在整图短摘要/详细白描之外，新增逐人脸的衣着、可见动作、手持物及位置记录。模型只接收编号人脸框、整图和局部拼图，不接收姓名或人物 ID；通过 `photo_faces.id` 关联当前人物档案，不从长描述中的“左边的人”等短语反推身份。

- 新表 `photo_person_observations` 只保存人脸 ID、源指纹和观察 JSON；不保存姓名或聚类 ID。改名、合并、拆分后读取当前人脸归属；换图、换框、重建人脸或换模型版本时旧结果不再有效。删除人脸级联删除观察，不修改原图、向量或聚类结果。
- `PHOTO_PERSON_OBSERVATIONS_ENABLED=1` 才会读写新表或自动排入后台；默认关闭。部署启用前需先执行 `20261016_001_photo_person_observations.sql`，以及上文尚未部署的详细描述迁移。
- 人脸处理及照片语义处理完成后均尝试补入观察任务，按同一源指纹去重；每组最多 4 人，共用已有 vision 执行通道。照片语义优先，人物观察优先于低优先级视频语义。上传响应不等待观察完成；没有自动扫描或重跑历史照片。
- 先生成结构化结果，再对同组图片进行一次复核。头身关系不确定时不展示衣着/动作；自由长篇人物叙述不入库，展示白描由结构字段拼接。诸如“主持、颁奖”等事件标签不从这轮观察直接确认为检索证据，仍留给特定查询核验。
- 搜索可以复用有效的逐人脸颜色证据，不必重新看图。任意自然语言动作尚未作为通用索引接入，不能据此宣称动作检索已全面实现。
- `GET /api/photos/:photoId/faces/observations` 沿用照片访问、人脸检索授权与访问审计。未授权用户和公开分享不获得人物绑定资料。普通详情只返回功能开关，不返回姓名。
- 查看器增加折叠的“人物观察”，展开后才请求；未齐全结果有限次轮询。切换/关闭取消旧请求，权限失败清除旧内容。电脑和手机使用同一可滚动阅读区，没有给相册列表增加大字段。

使用已有本地照片和人脸快照，在独立、只读、无业务数据库凭证的受限容器中运行校内 Hub 请求；没有修改生产环境。三人舞台约 7.25 秒，五人红旗现场两组约 13.65 秒，红背景前黑衣人物约 3.23 秒，均包含一轮生成和一轮复核。测试客户端 RSS 约 109–124 MiB，不是模型服务内存或整个网站内存，也不是并发吞吐结果。

真实样本仍有不足：有些字段输出英文；部分手持物被复核删除而产生漏检；海报样本未通过结构校验，拒绝发布属性。遮挡人物保留不确定状态。没有人工真值集，不能把成功返回的数量或模型自报的 clear 当作准确率。身份名称来自此前导出的本地档案快照，本轮没有认证档案的身份正确性。

完整后端 `npm test`、前端 `test:audit` 及生产构建通过，构建仍有既有体积告警。新增测试覆盖人物编号串绑、复核失败、重名/合并拆分后的当前归属、换框失效、颜色证据复用、后台分组调度与照片/人脸授权。浏览器验证展开时加载、未知属性隐藏、切图取消、权限错误和 1440/390 两种宽度布局。尚未在真实 MySQL 中执行新迁移或做全相册生产验收。

## 2026-10-16 不确定人物批次失败修复

- 原因：提示词要求头身归属不清时将 `profile` 留空，模型实际返回 `{}`；Hub 的严格字段校验却要求完整的衣着、动作、物件、位置结构。一人不确定就会拒绝同组所有人，三次重试也无法解决。生产照片 255、256、257 的只读复现均得到 HTTP 200、完整 JSON，报错是 `HUB_VISION_OUTPUT_INVALID`，不是对象存储或网络不可用。
- 修复：人物 profile 只接受完整的严格结构或显式空对象两种形式，不接受半填结构、错误类型或额外字段。空对象不会成为正向证据；两轮看图复核照常，头身不确定时仍清空身体属性。不更改人物来源指纹，因此已完成的有效结果无需失效或重跑。

# 上传者删除权限与本人上传筛选

2026-10-16 已测试并部署。没有修改账号角色、历史上传者或数据库结构。

## 权限边界

- 使用实际工作空间角色和授权判断，不以账号的 admin 文本直接放行。普通成员、编辑只能删除本人上传的照片或视频；上传能力保留。
- 小组管理员保留小组范围权限，学院管理员保留学院范围权限；跨组织、跨小组、受限相册和只读分享仍受原访问控制约束。
- 上传者未知的历史媒体不视为本人上传。混选其他人的媒体时整批拒绝；获取行锁后再次核对权限，防止预检查之后归属变化。
- 普通成员不能通过删除整个相册、修改 photographerId 或旧删除路由绕过限制。未改变其他编辑、新闻稿或工作台权限。

## 交互

- 相册操作的媒体筛选区新增独立“只看我上传的”开关，可与照片、视频筛选叠加，不改变原三项筛选的含义。
- 数量、空状态、预览翻页与选择遵循当前筛选；切换相册或用户时重置。单项预览不会翻出筛选范围。
- 选择栏支持仅选本人上传；普通成员删除按钮标注“删除我的”。相似照片仍可查看全部，删除入口只对有权限的内容显示。
- 删除只发一次请求；403 保留登录态和原始错误，不重复尝试其他写接口。

## 验证

- 后端新增 8 项回归通过：本人照片/视频、其他上传者、混合批次、未知上传者、角色层级、组织/小组/相册范围、行锁后再次核对、伪造上传者与相册删除绕过。
- 前端新增 4 项测试及完整 audit 通过；完整后端测试和实际发布镜像内测试通过。生产构建通过，仍有既有 bundle 体积告警。
- 真实 MySQL 集成使用外层事务与保存点，测试后全部回滚；覆盖本人照片/视频删除、其他人/混选/未知上传者拒绝和管理员行为，不执行对象存储清理。
- 完整页面模拟测试覆盖普通成员、小组管理员、学院管理员在电脑和手机上的选择、相似照片、403、本人筛选、视频叠加及预览导航。
- 生产接口检查所有 31 个普通成员、1 个小组管理员和1 个学院管理员；跨上传者删除被拒绝，普通成员上传权限保留。没有删除真实媒体。
- 生产浏览器在 1440 和 390 宽度验证有上传/无上传两种状态、筛选数量、可见内容和无横向溢出，无未捕获页面异常。
- 发布前后受保护媒体、人物、人脸、相册、文件夹摘要一致；后台描述和人物观察队列继续执行。

## 限制

没有做两条真实数据库连接同时竞争同一媒体的压测；锁后权限复核有回归覆盖，真实 MySQL 的锁定查询与回滚流程已验收。没有把界面隐藏当成后端授权。

新 API Pod 冷启动遇到一次数据库连接拒绝并自动重启，恢复后健康检查和生产接口验收通过。后台另有描述复核不可用的任务失败，未在本次权限改动中重置或掩盖；不宣称历史分析全部完成。

# 内容信息修改权限

2026-10-16 按用户确认收紧普通成员与编辑的修改权限，并保留明确授权的共同编辑。相册、照片/视频和文件夹分别按真实创建人或上传者判断，不根据账号的 admin 文本放行。

## 边界

- 普通同学只能修改本人创建的相册信息与环节，以及本人上传的照片/视频描述、标签、调色参数和环节归属。
- 明确的 collaborate 内部分享继续授权编辑；read 分享不会获得编辑能力，撤销后后端会再次拒绝。相册共享不会被误当成人物库授权。
- 新文件夹由后端记录 createdBy，创建人可以改名、移动和归类。旧文件夹没有创建人时仅管理员可改，不根据当前操作者猜归属。提交他人的 ID 或创建人字段不能接管已有文件夹。
- 小组管理员和学院管理员保留原访问范围，跨组织、跨小组及受限相册校验不放宽。个人置顶、外观等个人偏好不受共有文件夹编辑限制。
- 普通同学仍不能删除相册或文件夹；只能删除本人上传媒体的既有规则不变。上传到有上传权限的相册不要求成为相册创建人。

## 实现

共享工作空间校验增加 metadata 动作，区别于上传、删除、人物维护和其他业务动作。相册依据 projects.admin_id，媒体依据 photos.photographer_id；未知所有者不视为本人。读取时返回资源级 canEdit 与账号级 metadataEditScope，前端入口使用这些能力，不靠显示角色猜权限。

单照片 PATCH 和相册资料保存获取行锁后再次校验归属与当前共同编辑授权。批量环节调整严格验证所有 ID、先验证完整批次、锁定行后再次核对，再原子更新；混入他人或不可见媒体时不部分保存。相册和照片路由拒绝数字后缀等异常 ID，不能跳过参数级访问控制。

文件夹仍存储在现有 JSON 中，没有新增表或结构迁移。全量保存会比较锁定后的旧、新集合：不允许修改他人的已有字段或相对顺序，不允许通过遗漏 ID 绕过删除权限。createdBy 由后端创建并保留，客户端不能转移所有权；隐藏相册归属仍予以保留。个人偏好可独立保存。

外部转存的来源备注隐藏操作也使用 metadata 访问控制；任务管理不再把小组内普通同学的账号 admin 标签当成管理员授权。任务发起人的既有本人任务权限保留。

手机和电脑的玻璃、经典两套文件夹界面均按资源能力隐藏不适用操作；照片/视频编辑、调色保存、推荐标签和环节拖动也检查当前资源。权限失败不会把 403 当作登录过期而清除登录信息。

## 验证

- 新增 9 项后端权限回归：他人照片/视频、本人内容、异常相册 ID、明确共同编辑和只读分享、管理员、未知文件夹创建人、伪造/接管创建人、个人偏好、锁后归属变化、混合批次、来源备注与转存任务能力。
- 原相册/照片删除回归及文件夹版本、层级、隐藏归属保护回归通过。完整后端测试、实际发布镜像内测试通过。
- 新增 4 项前端能力测试，完整前端 audit 与生产构建通过；保留既有 bundle 体积告警。
- 完整应用的隔离浏览器验收共 16 组，覆盖两套样式、1440/390 宽度、普通编辑/两类管理员/共同编辑。本人及授权内容保留编辑入口，他人和历史文件夹无普通编辑入口；无横向溢出、未捕获错误或意外写请求。
- 真实 MySQL 使用外层事务与保存点验证实际权限模块和路由保存 SQL：本人相册、照片/视频修改成功，其他内容和混选被拒绝；只读/共同编辑/撤销流程符合预期；新文件夹创建人由后端绑定，历史文件夹仅管理员可改。所有测试变更回滚，原共享 JSON、版本号恢复，临时相册消失，没有调用对象存储写入或删除。
- 生产只读检查现有 31 个普通账号、1 个小组管理员、1 个学院管理员，核对资源 canEdit 与真实后端访问结果，上传与删除能力保留。两套样式、手机/电脑真实页面验证通过，没有操作真实内容保存。

## 运维说明

本轮不改用户角色、历史上传者、既有文件夹创建人，不迁移数据库，不重置后台分析。受保护的媒体、人物、人脸、相册、文件夹发布前后摘要一致。私有发布配置、截图、事务输入和验收输出位于忽略目录，不放入 Git；本轮未提交或推送。

没有执行两条真实连接同时撤销角色或授权的破坏性压力测试；锁后复核有回归和实际 MySQL 查询验收。旧 API 会放宽编辑权限并可能在保存时丢弃新的文件夹创建人字段，不能在开放写入时直接回退；应先进入维护状态并保留当前 JSON 与权限校验，不恢复旧数据库快照。

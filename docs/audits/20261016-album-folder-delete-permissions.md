# 相册与文件夹删除权限

2026-10-16 已测试并部署。普通成员与编辑不能删除相册或文件夹，包括自己创建的；小组管理员和学院管理员保留既有访问范围内的删除权限。没有修改账号角色或数据库结构。

## 发现与修复

相册的 projects.delete 已映射为小组 manage 权限，普通同学原本就被拒绝。本次发现异常 ID 如数字后接文本会跳过参数级工作空间检查，却被删除处理器截取为数字；已改为严格正安全整数校验，并在事务获取相册行锁后重新核对访问范围。

文件夹存储于共享桌面的 groups JSON。原接口允许编辑人员整理并提交全量状态，遗漏某个已有 ID 即可删除文件夹，没有独立删除授权。新增 canDeleteFolders：小组 manager 或学院管理员才可删除，旧版未启用小组的空间沿用 admin/superadmin；普通编辑不会因账号标签为 admin 获得小组删除权限。

删除通过锁定后的已保存 ID 与新 ID 集合做差判断，包括子文件夹、替换全部 ID、清空数组、附带个人偏好等保存路径。没有权限时整个事务拒绝，不写共享状态和个人偏好。创建、改名、排序、移动、归类等既有整理权限不扩大也不收回。

两套文件夹界面均读取服务端独立授权。缺失该字段时隐藏删除入口，按钮处理器也再次检查；相册沿用 /me 的 projects.delete。界面隐藏不是后端授权的替代。

## 验证

- 新文件夹回归先复现普通编辑清空 groups 返回 200，再修复为 403；验证伪造授权、子文件夹遗漏、替换 ID、个人偏好附带写、旧客户端层级保存及管理员放行。
- 新增 6 项相册路由回归，先复现异常 ID 与锁后范围改变的越权路径，再验证修复；覆盖成员/编辑、本人创建相册、小组/学院管理员、跨组织/小组、受限相册及匿名请求。
- 原照片删除 8 项回归、完整后端测试、实际发布镜像内测试、前端 audit 和构建通过；构建保留既有 bundle 体积告警。
- 完整应用的隔离浏览器验收共 20 组：两套样式、电脑/手机、成员/编辑/两类管理员/缺失新字段。管理员可删除，子文件夹回到上级，相册不受删除文件夹影响；普通编辑看不到删除按钮，仍可改名。没有横向溢出或未捕获页面异常。
- 真实 MySQL 验收使用外层事务与保存点，测试完整路由权限和 SQL。普通用户删除被拒绝，改名及管理员删除有效；全部回滚后原共享文件夹 JSON、版本号恢复，临时相册不存在。未调用真实对象存储清理。
- 生产只读检查 31 个普通账号、1 个小组管理员、1 个学院管理员的相册/文件夹删除授权，以及上传、整理权限。受保护媒体、人物、人脸、相册、文件夹发布前后摘要一致。

没有在生产删除真实相册、文件夹或照片，没有通过改角色解决问题，也没有重置后台分析。真实双连接并发角色撤销和大规模破坏性压力测试不在本轮范围。私有发布、配置、截图与事务验收记录保存在忽略目录，不写入 Git；本轮未提交或推送代码。

# 推文配图上下文

状态：2026-11-03 完成实现与本地测试，发布状态以学校服务器部署回执为准。复用现有表与字段，**不需要新增数据库迁移**。

## 接口约定

新闻预览、单次生成、批量生成及段落改写（`/api/ai/news/preview`、`/generate`、`/generate/batch`、`/rewrite`），以及公众号改稿（`/api/wechat-compositions/revision`），统一按照片 ID 在后端补全上下文：

```json
{"selectedPhotos":[{"id":123},{"id":456}],"projectId":78}
```

`projectId` 可选。仅将 ID 作为图库引用；客户端传来的照片描述、人名、相册快照及 `photoContext` 不作为权威数据。一次最多 30 张，重复 ID 去重。无效、已删除或无权访问的照片会拒绝请求，不静默跳过。资料超长会明确拒绝，不截断后冒充完整上下文。

后端读取照片摘要、详细描述、原文件名、摄影师、所属相册和时间线，以及有权限读取的当前人物 ID、姓名与绑定观察。改稿图片块可附带 `photoId`，必须属于本次 `selectedPhotos` 中已授权的照片；没有关联时，不允许模型按图题或排列顺序猜测。

## 权限与事实边界

- 每次请求重新检查组织、工作空间和共享访问权限；旧工作空间同样检查。只获得个别照片共享权，不等于获得整个相册的描述和时间线。
- 没有人物检索授权时，不查询或提供人物姓名、人物 ID、观察信息。普通照片描述仍按既有照片阅读权限提供，不另行抹除其中已有的人名。
- 人物关联使用 `photoId / faceId / personId`，姓名在读取时解析，不靠同名匹配。只有 `status=ready` 且 `binding=clear` 才提供衣着、动作等绑定属性。
- 复用 `photo_person_observations` 的 source-key 校验。人脸框、照片源或模型版本改变后，旧观察不再使用；更名或修正人物归属不改写视觉观察。缺失或失效观察为 `not-analyzed`，不确定绑定为 `uncertain`，均不能当成确定事实。
- 相册资料是归档背景；机器描述和人物识别是线索，不自动成为已确认的出席身份、职务、发言或成果。不向模型传人脸向量或图片签名 URL。

## 旧稿兼容与验证

改稿请求会从当前已选素材发送去重的照片 ID。图片块含 `PHOTO:id`，或与当前素材的 URL 精确且唯一对应时，前端附上 `photoId`；后端再次校验它属于本次授权照片。图片 URL、缓存姓名不进入改稿请求。模糊对应或不同照片复用同一 URL 时不猜测。

旧手动编辑器里只有 URL、没有照片 ID 或素材记录的图片，**不会在后端凭 URL 反查恢复关联**；须重新选择图库照片或保留明确的照片 ID。仅有 `selectedPhotos` 而图片块没有 `photoId` 时，可以提供整体配图背景，但不能保证逐个图注对应。

`npm run test:news` 已包含补全与路由测试，覆盖伪造快照、越权、共享撤销、无人物权限、改名、绑定不确定和生成／改稿入口。source-key 失效及观察状态另由现有 `test_photo_person_observations.js` 回归保障；人物读取授权由 `test_photo_person_access.js` 覆盖。测试使用本地模拟依赖，不修改生产数据。
